0	音乐歌曲比对项目
1	1 项目背景
2	音乐是数字时代最容易被复制和传播的内容之一。一首歌走红后，网络上很快会出现各种版本：有的是作者本人的原唱，有的是别人重新演唱的“翻唱”，还有的是未经授权直接套用他人作品或旋律的“搬运”。面对海量上传的歌曲，如果全靠人工一首一首去听、去比对，既费时费力，又容易因为主观判断而出现分歧。
3	我们希望交给计算机来做这件事：让程序自动判断“两首歌曲是什么关系”。例如，当我们输入原曲和一段复刻版时，程序应该判断为“搬运”；输入原曲和另一人演唱的相同旋律时，判断为“翻唱”；输入两首完全不同的歌时，判断为“不相关”。
4	这个问题的本质，是把人的“听起来像不像”这一主观感受，转化成程序能够计算的数字。我们需要先从歌曲中提取出能代表其特点的数字信息，再比较这些信息之间的差距，最后根据差距的大小给出判断。对大一新生来说，这是一个非常合适的第一门综合实践项目：它不需要太高深的数学，却能把“读文件、提取特征、计算距离、做出判断”这一整套程序设计思路完整地走一遍。
5	2 项目目标
6	2.1 功能目标
7	编写一个 Python 程序，输入两首歌曲的音频文件（如 mp3、mp4 或 wav），程序自动输出三类结论之一：搬运、翻唱、不相关。程序应给出一个可量化的相似度得分，并据此说明判定依据。
8	2.2 学习目标
9	通过完成本项目，希望你能初步掌握以下能力：
10	一是掌握 Python 基础与常用第三方库（numpy、librosa、matplotlib）的基本用法；二是理解音频数字化中的采样率、声道、时长等基本概念；三是学会提取音乐的节奏、音高、音色等特征；四是理解余弦相似度、欧氏距离等相似度度量，并能在代码中实现；五是建立“特征提取—距离计算—阈值分类”的完整问题求解思路；六是掌握用准确率、混淆矩阵等方法评价程序效果的基本方式。
11	3 关键技术
12	3.1 音频读取与预处理
13	计算机无法直接理解声音，我们需要先把声音文件读成一组数字。常用工具是 librosa 库，它能把音频变成以“帧”为单位的数值序列。为了让两首歌可以公平比较，预处理阶段要做三件事：统一采样率（如都转成 22050Hz）、统一声道（一般转成单声道）、统一比较时长（只取前几十秒或归一化长度）。

53	3.4 分类判定
54	得到相似度得分后，需要设定一个规则把它变成“搬运 / 翻唱 / 不相关”三类结论。最直接的方法是阈值法：先综合多个特征计算一个 0 到 1 之间的总相似度，再按阈值划分。示例如下（具体数值需根据你的数据调整）：
55	若综合相似度不低于 0.85，判定为“搬运”；若在 0.55 到 0.85 之间，判定为“翻唱”；若低于 0.55，判定为“不相关”。
56	进阶一点的做法，是把“特征向量 + 类别标签”喂给简单的机器学习分类器（如支持向量机 SVM），让程序自动学习阈值。这一步学有余力的同学可以尝试，不做硬性要求。
57	4 技术路线
58	4.1 总体流程
59	项目整体按“输入—预处理—特征提取—比对—分类—输出”的顺序进行，流程如下：
60	第 1 步，读入两首歌曲的音频文件；第 2 步，对音频做统一采样率、声道、时长的预处理；第 3 步，分别提取两首歌的 Chroma、MFCC、节奏等特征；第 4 步，计算两首歌在各项特征上的相似度；第 5 步，综合各相似度得到总得分，按阈值判断类别；第 6 步，把结果和相似度得分打印出来。
61	4.2 环境搭建
62	建议使用 Anaconda 安装 Python，然后在命令行中安装依赖库，命令如下：
63	pip install numpy librosa matplotlib soundfile
64	安装完成后，可以在 Python 中运行 import librosa 验证是否成功。若遇到安装报错，可先更新 pip（python -m pip install --upgrade pip）再重试。
65	4.3 模块设计与实现
66	为了让程序结构清晰、便于调试，建议把项目拆成几个小模块，每个模块负责一件事。
67	第一个是预处理模块 preprocess.py，函数 load_audio(file_path) 负责读取音频并统一采样率、声道和时长，返回处理后的声音数据。
68	第二个是特征模块 features.py，函数 extract_features(audio) 负责从声音数据中提取 Chroma、MFCC、节奏等特征，返回一个特征向量。
69	第三个是比对模块 compare.py，函数 similarity(feat1, feat2) 负责计算两首歌的综合相似度得分。
70	第四个是分类模块 classify.py，函数 judge(score) 负责根据阈值把得分转换为“搬运 / 翻唱 / 不相关”。
71	把大问题拆成小函数，是程序设计的重要基本功，也方便你分别测试每一部分是否正确。
72	4.4 主程序运行
73	编写主程序 main.py，把上述模块串起来。运行方式示例：
74	python main.py song1.mp3 song2.mp3
75	程序输出示例：两首歌的综合相似度为 0.92，判定结果：搬运。

96	5.2 实验设计
97	为了找到效果最好的方案，可以设计对照实验：分别比较不同特征组合（只用 Chroma、只用 MFCC、Chroma+MFCC+节奏）与不同相似度方法（余弦、欧氏、相关系数）的搭配，逐一记录正确率。实验中把一部分样本用于设定阈值（训练），另一部分用于验证效果（测试），避免用同一批数据既调阈值又评价结果。
98	5.3 评价指标
99	判断程序好不好，不能只看个别例子，要统计整体表现。常用指标有：准确率（判断正确的样本对占总样本对的比例）、精确率（被判为某一类的结果中真正属于该类别的比例）、召回率（某一类样本中被正确找出的比例）、F1 分数（精确率与召回率的综合）。此外，还可以用混淆矩阵直观地看程序在哪一类上最容易出错。
100	5.4 实施步骤
101	建议按以下顺序推进实验：第一步，收集并整理样本对，记录每对的真实类别；第二步，写好特征提取和相似度计算代码，对每对样本算出各相似度；第三步，用训练集确定合适的阈值；第四步，在测试集上运行分类，统计准确率和混淆矩阵；第五步，调整特征组合或阈值，观察结果变化，找出最优配置。
102	5.5 结果分析与改进方向
103	实验完成后，重点分析哪些特征最有效、程序在哪些类别上容易误判。常见改进方向有三个：一是对音频做对齐，消除演唱速度快慢带来的影响；二是增加更多特征，提高区分度；三是采用更精细的片段级比较，而不是只取整首的平均。这些都可以作为学有余力时的进阶尝试。
